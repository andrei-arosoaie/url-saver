Phase 7 · Article Connections & Semantic Similarity

Connect what you save.

Discover related articles through shared entities and similar ideas, with a clear reason for every suggested connection.

Preserve the approved entity types and manual corrections. This phase does not automatically expand the entity taxonomy or rewrite existing links.

Architecture & storage

  • Use existing Supabase PostgreSQL: enable pgvector for embeddings and similarity queries. No separate vector database.
  • Save first, process afterwards: embedding generation runs outside the capture/save request so saving remains fast.
  • Source text: derive plain text from stored sanitized article HTML; keep captured content unchanged.
  • Track embedding provenance: article/content version, model/version and dimensions. Avoid comparing incompatible embedding models or stale content versions.
  • Account isolation: shared-entity lookup and vector retrieval must enforce ownership. Never return another account’s content through related results.
  • Distinct evidence: shared entity IDs/links explain explicit connections. Similarity scores are model outputs, not proof of a factual relation.
  • Independent processing: failures or pending embeddings do not prevent reading saved content or using existing explicit links.

Embedding provider/model, article versus chunk embeddings, thresholds/top-result count, refresh/retry rules and index tuning need technical review. No embedding model or external provider is selected yet.

Implementation guide

  1. Review related-content UI, connection reasons, embedding model and processing/storage contracts.
  2. Implement owner-scoped shared-entity related-article queries.
  3. Add pgvector schema and asynchronous embedding processing with content/model version tracking.
  4. Expose related articles with evidence and separate similarity suggestions from explicit connections.
  5. Verify save responsiveness, version refresh, ownership, failures and result relevance with repeatable fixtures.
