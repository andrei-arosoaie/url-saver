Articles / API

Endpoints

Four article contract baselines approved. Use View contract for requests, responses, errors and remaining details. Identity and token endpoints live in Security architecture.

FeatureOperationPurpose
articlesPOST/api/v1/articlesSave URL, title, and optional extracted HTML. Apply exact URL duplicate rules and the configurable 4 MiB content limit. Existing content: return 409 with the existing article ID and prompt; automatically enrich missing content without a prompt.
articlesPATCH/api/v1/articles/{articleId}Explicitly update an owned saved article after user confirmation. Existing content is otherwise preserved.
articlesGET/api/v1/articlesList the caller’s saved articles, newest first. Return summaries without full article HTML.
articlesGET/api/v1/articles/{articleId}Return one owned article, including saved content or its link-only state. Missing or owned by another account: 404.

Pagination

Cursor pagination, newest first. The first request returns the latest batch; subsequent requests send the returned cursor to load older articles.

Start small: no page-number jumps or oldest-first control. Batch size: 20 by default, maximum 100. Response: items + nextCursor. Cursor bookmark uses the last savedAt + article UUID, encoded and validated by the backend. Internal encoding is an implementation detail; use the simplest solution.

ConcernDesign
OwnershipEvery article query is scoped to the authenticated account_id. Other-account and missing articles both return 404.
DuplicatesOne saved article per account and exact URL. Reuse the existing article; offer Update existing / Cancel when content exists. Automatically fill missing content. Never silently normalize or overwrite content. Separate copies are outside current scope.
Article contentTEXT stores sanitized extracted HTML only; nullable for link-only items. Enforce the configurable 4 MiB UTF-8 limit before sanitization and on sanitized output; reject either oversized value.
Cursor indexConfirmed ordering: saved_at DESC, id DESC. Proposed supporting index: (account_id, saved_at DESC, id DESC). Timestamp plus UUID provides a deterministic newest-first boundary.
Article preservationAll article text must remain. Remove unsafe markup/attributes without deleting article prose. Preserve text inside unsupported formatting. No silent content truncation or link-only downgrade when content was supplied. Verify article-text preservation in tests.
SanitizationOWASP Java HTML Sanitizer before persistence. Keep headings, paragraphs, emphasis, lists, quotes, code blocks, tables, and HTTP/HTTPS links. Remove images, scripts, forms, embeds, event handlers, inline styles and page-specific CSS classes. Store only sanitized HTML; never retain raw captured HTML.
Concurrent updatesVersion-based optimistic locking. Reject stale updates rather than silently overwrite a newer change. Rare conflicts can occur across tabs/devices for the same account. JSON version in responses and PATCH. Starts at 0; increments on every actual change, including enrichment. Stale updates return 409 with an explicit version-conflict reason; reload before another explicit update. No automatic overwrite/retry.
URL lookupUnique B-tree index on (account_id, url_hash). url_hash is generated by the application as the SHA-256 digest of the exact URL; original URL remains unchanged in TEXT. On conflict, compare full URLs. Same URL: apply existing duplicate/enrichment rules. Different URLs with the same hash: explicit collision error; never update the other article. Database CHECK verifies the application-supplied hash against SHA-256 of the exact URL.
Schema changesFlyway owns migrations. JPA entities stay in infrastructure; Hibernate validates schema.
