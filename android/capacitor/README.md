# Know Android — Capacitor (active)

Phase 13 now uses Capacitor. The React application stays the source of truth for the interface: **no copy of the screen components, CSS, logo or business UI is maintained here**. The previous Compose prototype is preserved in [`../kotlin/`](../kotlin/README.md).

## Current checkpoint

The initial Android shell packages the existing interactive preview. It imports `webapp/design/android-preview.tsx`, which renders the real `webapp/src/App.tsx`, profile controls and CSS with fictional, in-memory adapters. This lets us verify reuse on Android before connecting real accounts. The package is deliberately named **Know Preview** with ID `com.know.mobile.preview`; it is not a production client.

The preview does not authenticate, save to Know, or implement all backend mutation semantics. Its fixtures are not a replacement for the existing server. Native sign-in, secure token storage, API routing and Share to Know are the next integration checkpoints.

## Folders

- `src/`: thin Capacitor bootstrap and Android navigation integration.
- `native/`: Android Studio/Gradle project generated by Capacitor, retained as source. Custom Android plugins will live here.
- `tests/`: checks for the mobile shell behavior.
- `dist/`: generated web bundle, ignored.
- `../../webapp/src/`: shared application components, styling and API/domain code.

## Build and run

Use Node.js 22.12 or newer, JDK 21, and Android SDK platform 36 with build tools 36.0.0. Install the web app dependencies too because the shared source remains in that project.

```powershell
npm ci --prefix ../../webapp
npm ci
npm run check
npm run android:sync
cd native
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

Set `ANDROID_HOME` or an ignored `native/local.properties` with `sdk.dir` for your machine. Run `npm run android:open` from this folder to open the native project in Android Studio. The debug APK is `native/app/build/outputs/apk/debug/app-debug.apk`.

`npm run test:browser` verifies the actual packaged bundle in desktop Chrome at phone/tablet dimensions and writes evidence under `.tools/capacitor-browser-proof/`. This is a browser check, not an emulator/device run. With an emulator or device attached, run `:app:connectedDebugAndroidTest` from `native/` to execute the native WebView and Back-dialog tests; assembling that test APK alone does not execute them.

`android:sync` packages local assets. There is no remote `server.url`, permissive navigation allowlist, plaintext API connection or embedded production secret. Browser verification is useful but does not establish device behavior; physical phone/tablet validation remains required before release.

## Next implementation checkpoints

1. Native Google/backend PKCE authorization in a system browser, distinct Android client registration, verified callback and secure refresh-token storage. Keep the web authentication behavior unchanged.
2. Authenticated mobile transport for existing API clients; preserve versions, error handling, precise timestamps, account isolation and no automatic mutation replay.
3. Replace fixture adapters with real account data while keeping the same shared React screens. Validate the complete parity checklist against a disposable backend.
4. Deliver [Phase 14 - Share to Know](../../specs/phase-14/design.md): add the native receiver/plugin and category selector, retain pending links across launch/sign-in, and extend the existing save API for atomic category-on-create support. A shared URL alone does not include the browser DOM or screenshot.
5. Verify Android Back, modal dismissal, keyboard/insets, accessibility, resizing, reader isolation and lifecycle on phone/tablet hardware; prepare signing and release separately.
