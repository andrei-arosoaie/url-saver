Authentication

Google sign-in → Know account → PKCE authorization code → Know JWT and rotating refresh token.

Authorization

Validate the token and session. Read the trusted account ID from Security context. Restrict article queries to that account; return 404 for other-account articles.

Signing in leaves existing sessions active. Webpage uses JWT/refresh tokens: access token in memory, refresh token in a Secure HttpOnly cookie. Shared lifetimes, reload renewal, one renewal/retry after expired-token 401, coordinated cross-tab refresh and current-session logout are approved. Shared token endpoint confirmed; cookie/CSRF details remain to agree.

Approved renewal & logout: Webpage and extension share configurable lifetimes: initially 24-hour access tokens and a 24-hour refresh window from sign-in. On reload, silently refresh using the cookie. On an expired-access-token 401, renew once and retry that request once; failed renewal requires sign-in. No automatic retries for duplicate/version conflicts. Serialize refresh across webpage tabs. Logout revokes only the current sign-in session and immediately rejects its JWT and refresh tokens; other sessions remain active.

Webpage token storage

Approved: Webpage access token stays in memory only. Refresh token is stored in a Secure HttpOnly cookie and rotated by the backend. No refresh token in webpage JavaScript, localStorage, sessionStorage or JSON responses. Cookie scope/SameSite, CSRF and shared-endpoint cookie transport still require agreement. Cross-tab refresh coordination and current-session-only logout are approved. This remains JWT/refresh-token authentication, not a server-side login session.

One shared authentication and refresh mechanism for extension and webpage. Use the same token endpoint and lifecycle logic. Approved storage differs: extension storage versus webpage memory/HttpOnly cookie; no separate webpage refresh endpoint.

Independent identity and accounts

identity

Who is calling?

Google sign-in integration, external-provider-to-Know-account mapping, OAuth authorization, JWT issuance, refresh-token lifecycle, sessions, revocation, and logout.

presentationAuthentication entry points and security-protocol integration.
applicationIdentity use cases, session policies, exposed contracts, and repository ports.
infrastructureSpring Security adapters, persistence adapters, JPA entities, key/configuration integration.

Authorization-server concerns stay isolated here to support future extraction.

accounts

Which Know account?

Creates and manages provider-independent Know accounts. Identity owns the mapping from external provider identities to Know account IDs.

presentationPackage reserved for account-facing adapters; no new account UI or endpoints approved.
applicationAccount creation and management use cases; exposed application interfaces.
infrastructureAccount persistence adapters and JPA entities.

An account feature does not introduce a profile-management or deletion workflow by itself.
