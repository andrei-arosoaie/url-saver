Phase 10 · Entity management

Remove entities. Keep viewing clear.

This phase covers the latest requested changes: deleting entities, editing completion timestamps with a date picker, showing viewing progress toward all released episodes, matching the approved TV show header design with expandable posters, and hiding redundant TV viewing controls when every available released episode has been watched. Movie integration is preserved in Phase 11.

Implemented and verified locally. All Phase 10 requirements below are covered. Production deployment is separate.

1 · Entity deletion

Allow the user to delete a book, movie, TV show or game from its entity details. Show a confirmation naming the entity and explaining that its completion history, viewing progress and article associations will be removed permanently. Keep the linked articles and their saved content.

Cancel leaves the entity untouched. Confirm removes it only after the server succeeds, closes its details and refreshes the list. Show failures clearly. A stale version requires reloading and a fresh confirmation; never retry a destructive request automatically.

2 · Completed viewing controls

When catalog data confirms that all released episodes are watched, hide the entire Last watched fieldset, including both selectors and both save buttons. Also hide Mark show seen. Keep the viewing progress bar, watched/released counts, caught-up state and episode browser visible.

Calculate completion from watched episodes against available episodes released to date, not from the show status or the last selected episode. Future, unavailable and special episodes follow the existing regular-episode counting rules. Unknown or empty catalogs must not imply that everything is watched.

When a newly released episode becomes available through the existing catalog refresh, update the progress denominator and remaining count and show the applicable viewing controls again. Exclude watched episodes and fully watched seasons from the Last watched choices; keep them available in the episode browser.

3 · Completion date picker

Edit timestamp must open a date and time picker for completion history. Prepopulate it with the saved timestamp in the user's local time and convert the selected value to UTC when saving. Do not require typing an ISO timestamp.

Support saving and cancelling, validate the selected date and time, and show pending and error states. Cancelling or saving without changes must preserve the original timestamp, including its stored precision. Use the existing ownership and version checks.

4 · Viewing progress bar

Show a clear progress bar in the TV show table's Progress column and in TV show details, alongside watched/released episode counts, a percentage and the number of episodes remaining to catch up. Align the table with the approved mockup, including season and episode progress.

Calculate the percentage as watched released episodes divided by all available regular episodes released to date. Show 100% and a caught-up state only when that nonempty set is fully watched. Exclude future and unavailable episodes; show an explicit unknown or no-released-episodes state rather than a misleading full bar.

Refresh the catalog through the existing background update mechanism and refresh visible progress accordingly. When new episodes are released, increase the total, update the percentage and remaining count, and restore the relevant viewing controls without requiring a manual progress edit. Expose accessible progress values and readable text on desktop and mobile.

Identify the rating source in TV show details: display Rating: 7.7/10 with a small, muted TVMaze source link beside it, linking to that show on TVMaze. Keep the attribution discreet, with no badge or extra decoration. Use the actual provider score without changing its value; omit the rating when unavailable. The adjacent IMDb link must not imply that this is an IMDb rating.

TV show header and poster preview

Match the approved TV show details mockup: a compact poster on the left; a small uppercase TV SHOW label, prominent show title, and a compact metadata line on the right. Include premiere year, genres, provider status and runtime when available. Keep the rating and IMDb link on the next line, with a discreet TVMaze rating source link. Place the viewing status badge and added date together below the main header. Avoid the current separate, stacked information block.

Use the actual poster and metadata, preserving its aspect ratio and handling missing fields without empty separators. Respect the existing theme, spacing and typography. Adapt the layout for narrow screens without clipping the title, metadata or links.

Make the poster a keyboard-accessible button that opens a larger version of the image in a modal preview. Fit the image within the viewport without distortion; provide a clearly labelled close button, Escape dismissal, focus containment and return focus to the poster when closed. Supply meaningful alternative text. If a larger provider image is available, use it; otherwise enlarge the existing image. A missing-poster placeholder must not open an empty preview.

In Add TV show search results, enlarge the poster thumbnails from 30 by 42 pixels to approximately 54 by 76 pixels so shows are easier to distinguish. Preserve image proportions, keep titles and years readable, and retain a scrollable dropdown that fits desktop and mobile viewports. Keyboard navigation must scroll the active result into view.

Entity dates follow timeline rules

Use the same date display rules as the timeline for entity Created dates in tables and cards and the Added date in details. Reuse the existing timelineDate formatter instead of maintaining a separate entity date convention.

  • Same local calendar day: Today.
  • Previous local calendar day: Yesterday.
  • Two through six local calendar days ago: full weekday name.
  • Older dates: numeric day and abbreviated month; include the year only when it differs from the current local year.

Respect the user's locale and time zone, including daylight saving and year boundaries. Preserve the original timestamp in the time element's dateTime attribute and expose the full local date and time using the existing exactCaptureTime formatter as a tooltip. Date-only table cells remain date-only; do not add a clock merely to match the timeline layout. This changes presentation, not stored timestamps or sort order.

5 · Ownership, consistency and cleanup

Implement deletion through the existing entity application service and account-scoped store. Require the current entity version, reject stale writes, return the existing missing-resource response for unknown or foreign entities, and perform all cleanup in one transaction.

Remove the entity's completion history, article links, TV mapping, episode watches and connection reasons. Preserve other entities, other accounts, shared provider catalogs and article content. Recompute or invalidate affected article connections; preserve connections supported by remaining reasons or semantic similarity. Coordinate deletion with concurrent connection processing so foreign-key failures or stale jobs cannot recreate deleted associations.

Expose and document the deletion contract in OpenAPI and regenerate affected client types. Use existing error conventions and audit the affected list, details and connection views for stale references.

6 · Implementation and acceptance

  1. Implement transactional, account-scoped deletion with version checks and dependent-record cleanup.
  2. Add entity-details deletion with an accessible confirmation, cancellation, pending state, success navigation and recoverable failure state.
  3. Hide the completed-viewing controls using released episode counts, retaining the progress display and episode browser. Restore the controls when refreshed data contains unwatched released episodes.
  4. Match the TV show header to the approved mockup on desktop and mobile, including the status and added date row, compact metadata and discreet rating attribution. Verify larger search-result posters, readable titles and years, viewport fit and keyboard scrolling. Verify poster enlargement by mouse and keyboard, closing with the button and Escape, focus restoration and missing-poster behavior.
  5. Reuse timeline date formatting for entity Created and Added labels; verify Today, Yesterday, weekdays, older dates, year boundaries, local midnight and daylight saving behavior, plus the exact timestamp tooltip.
  6. Add or verify the completion date and time picker: saved value prepopulation, local-time/UTC conversion, cancellation, unchanged timestamp precision, validation and failed saves.
  7. Add or verify the viewing progress bar in the TV table and details: accurate counts, percentage, remaining episodes, accessible values and refreshed progress after a new release.
  8. Verify deletion with attached history, article links, TV watches and connection reasons; verify cross-account isolation, stale versions and retained articles and shared catalogs.
  9. Verify cancellation, failed deletion, successful list removal, caught-up state, partial viewing, unknown and empty catalogs, and a new episode arriving after completion. Run appropriate backend, webapp and contract checks and inspect desktop and mobile layouts.

Keep production credentials and signing keys uncommitted. Do not mark this phase complete until the implementation and required checks pass.

7 · Implementation evidence

Phase 10 is implemented and verified locally. Entity deletion uses an owned, version-checked DELETE request and transactional cleanup. Concurrent edits, article deletion, connection processing, retained articles and shared catalogs are covered. The webapp includes the local date and time picker, released-episode progress, completed-control hiding and restoration, timeline date labels, compact TV header, discreet rating attribution, enlarged poster preview and larger autocomplete posters.

  • Backend: 44 unit and architecture tests plus 88 PostgreSQL integration tests passed. The exported OpenAPI contract matches the checked-in contract, including deletion and TV poster source fields.
  • Webapp: lint, formatting, 143 tests, type checking and production build passed.
  • Firefox extension: generated API types, type checking, lint, formatting, 71 tests and production build passed.
  • Local browser verification passed at 1600, 1024, 390 and 320 pixel widths: progress layout, filtered episode choices, poster preview and dismissal, local-time conversion, confirmed deletion, larger search posters and no horizontal overflow. Desktop and mobile screenshots were inspected.

Verification used disposable database fixtures and a local mocked browser application. Production deployment is separate. Movie integration remains in Phase 11.
