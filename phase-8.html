Season & episode selection

User chooses the season and episode last watched. Persist their position in Know, scoped to their account/TV-show entity. TVMaze metadata refresh must never move the user’s position automatically.

After selecting a position, ask whether to mark regular episodes through and including the selected episode as watched. On confirmation, record those watched flags; otherwise save only the position, leaving existing watched flags unchanged. Position and episode watch state are separate. Store provider IDs to identify shows, seasons and episodes reliably. Do not treat season/episode numbers as globally unique. Episode numbers, dates, summaries and images may be absent; specials and alternate ordering need explicit handling.

Approved: last episode watched; confirmed bulk marking or position-only save; automatic linking only for an unambiguous show match, otherwise ask; regular episodes only initially. Review next: exact unambiguous-match criteria, future-episode eligibility and remaining progress/refresh edge cases. Approved TV-show statuses are To be seen / Seeing / Seen; Seeing is the active-viewing state.

Architecture & cost

React webapp → Spring Boot → TVMaze public API. The public show API is free; no paid TVMaze account is required for this catalog scope. Keep user watch progress locally in Know rather than integrating TVMaze premium user-account features.

Search by show name and retain the selected TVMaze show ID. Automatically link only an unambiguous match; otherwise ask the user to choose. Exact safe-match criteria require contract review. Separate provider metadata/cache from account-owned entity/progress data; preserve manual titles and existing entity identity.

Cache catalog responses and share public metadata across users; keep each user’s progress private. Fetch only the linked shows and required season/episode information rather than downloading the entire TVMaze catalog. Refresh cadence is configurable 24h; catalog/progress schema and API drafts appear below.

Handle TVMaze rate limits and transient failures independently of Gemini. TVMaze documents at least 20 calls per 10 seconds per IP and recommends a short pause on 429; do not apply the Gemini 24-hour cooldown to this provider. Keep cached information and user progress available during outages.

Sanitize provider HTML summaries before display. Show clear TVMaze attribution with a source link; API data is provided under CC BY-SA and its ShareAlike conditions apply. Official API, caching, rate-limit and licensing documentation.

Approved progress behavior

  • Selected season/episode means last episode watched.
  • Ask whether to mark regular episodes through the selected position as watched. Confirmation records watched flags; declining records only the position and preserves existing flags.
  • Automatically link an unambiguous TVMaze show match; ask when ambiguous.
  • Regular episodes only initially. Filter specials from season responses before showing/selecting or bulk marking.
  • Approved show fields: poster, synopsis collapsed until expanded, genres, provider running/ended status and typical episode runtime. Other display fields remain for individual selection.

Unit and end-to-end integration tests must verify confirmed bulk marking versus position-only updates, regular/special filtering, ambiguous matches and per-account isolation.

Approved show details

  • Poster. Use a placeholder when no image is available.
  • Synopsis, collapsed by default. Expand on request; sanitize provider HTML.
  • Genres.
  • Running/ended status. Keep separate from the user’s Seen / To be seen status.
  • Typical episode runtime. Do not invent a value when missing.

Approved episode details

  • Season/episode numbers and episode titles.
  • Episode air date and runtime when available.
  • Episode summaries collapsed until expanded. Sanitize provider HTML.
  • Episode images visible by default. Missing images use a placeholder.
  • Upcoming episode number, title and air date when TVMaze provides them.

Approved episode-image visibility supersedes the earlier suggestion to hide images for spoilers. Do not hide titles or images by default.

Approved watch controls & show status

  • Individual watched/unwatched episode checkmarks are available independently of position selection.
  • Moving the saved position backward changes the position only; previously watched flags remain. A confirmed bulk-mark action may add watched flags, never silently unmark them.
  • When all aired regular episodes are watched, offer Mark show seen. Do not change the show status or append show completion history without the user choosing that action. Use the existing explicit completion behavior after confirmation.
  • Show TVMaze’s community show rating, clearly labelled, when available.
  • No cast section.

Progress, position and show-level completion are separate user-owned state. TVMaze refresh preserves position, watched flags and completion history. It may change current status under the approved newly-aired-episode rule. Only aired regular episodes are watchable. Newly aired unwatched episodes automatically change a Seen show’s current status; change it to To be seen. Preserve earlier completion history.

IMDb link

Include the IMDb show link when TVMaze supplies an externals.imdb ID. Omit the link when unavailable; do not guess IDs.

IMDb scores are deferred. No OMDb integration, IMDb ratings dataset or extra API key is required for Phase 8. Continue displaying the approved TVMaze community rating, clearly labelled TVMaze.

Airing rules & catalog refresh

  • Only aired regular episodes can be marked watched. Future episodes remain visible as upcoming. Validate eligibility on the backend using provider timestamps where available; unknown airing information allows explicit manual watched marking; do not infer that it aired or auto-bulk-mark unknown-date episodes.
  • Unchecking an episode changes only that watched flag; the separately saved last-watched position remains unchanged.
  • When a new regular episode has aired after the show was marked Seen, automatically change current status and indicate new episodes available. Preserve all existing completion history; never append a completion merely because metadata refresh found a new episode. The destination status is To be seen. Announcing a future episode alone does not trigger the change.
  • Metadata cache: 24 hours initially, configurable. Serve cached details immediately and refresh stale linked-show data in the background. Refresh must preserve personal progress and manual titles; keep cached data available during provider failure.

Approved: offer Mark show seen after all aired regular episodes are watched; unaired episodes do not block the offer and must not be marked watched. The user must choose the action before status/completion is recorded.

Database design

Shared catalog, private progress. Eight proposed tables. Provider refresh must not overwrite personal titles, position, checkmarks or completion history. Field reference · ER source.

tvmaze_shows · Shared public metadata

tvmaze_id BIGINT PK; name TEXT; poster_url TEXT NULL; summary_html TEXT NULL; genres JSONB; provider_status TEXT NULL; average_runtime INTEGER NULL; rating NUMERIC NULL; imdb_id TEXT NULL; next_episode_id BIGINT NULL; provider_updated_at TIMESTAMPTZ NULL; fetched_at TIMESTAMPTZ; version BIGINT

Store only selected display fields plus provenance. TVMaze rating is not IMDb rating. Sanitize summary HTML.

tvmaze_seasons · Shared season catalog

tvmaze_id BIGINT PK; show_id BIGINT FK; number INTEGER; name TEXT NULL; premiere_date DATE NULL; end_date DATE NULL; fetched_at TIMESTAMPTZ; version BIGINT

Show/season IDs identify provider records. Do not use the season number as a global key.

tvmaze_episodes · Shared episode catalog

tvmaze_id BIGINT PK; show_id BIGINT FK; season_id BIGINT FK NULL; season_number INTEGER; number INTEGER NULL; episode_type TEXT; name TEXT; air_at TIMESTAMPTZ NULL; air_date DATE NULL; runtime INTEGER NULL; image_url TEXT NULL; summary_html TEXT NULL; fetched_at TIMESTAMPTZ; provider_present BOOLEAN; version BIGINT

Retain unavailable/deleted provider IDs referenced by progress; do not cascade-delete personal state. Select/watch regular aired episodes only. Missing time handling is highlighted for review.

entity_tv_shows · Private mapping, position and show-seen watermark

account_id UUID; entity_id UUID; show_id BIGINT FK; alias TEXT NULL; last_watched_episode_id BIGINT NULL; last_marked_seen_at TIMESTAMPTZ NULL; new_episodes_available BOOLEAN DEFAULT FALSE; created_at TIMESTAMPTZ; updated_at TIMESTAMPTZ; version BIGINT

PK(account_id, entity_id), owner-checked FK to entities. Validate entity type TV_SHOW. Position and checkmarks are independent; manual entity title is never replaced by provider refresh.

entity_episode_watches · Private episode checkmarks

account_id UUID; entity_id UUID; episode_id BIGINT FK; watched_at TIMESTAMPTZ; version BIGINT

PK(account_id, entity_id, episode_id). Composite FK to entity_tv_shows. A row means watched; explicit uncheck removes it. Validate episode belongs to the mapped show. Not an episode rewatch-history feature.

tvmaze_refresh_jobs · Durable, shared catalog refresh

show_id BIGINT PK/FK; requested_at TIMESTAMPTZ; available_at TIMESTAMPTZ; status TEXT; lease_token UUID NULL; lease_until TIMESTAMPTZ NULL; attempt_count INTEGER; last_error_code TEXT NULL; updated_at TIMESTAMPTZ

One coalesced refresh per show. Short claim transaction with SKIP LOCKED, expiring leases and fencing. Reuse a public catalog across accounts; never send personal progress to TVMaze.

tvmaze_provider_state · Independent provider backoff

quota_scope TEXT PK; blocked_until TIMESTAMPTZ NULL; last_http_status INTEGER NULL; updated_at TIMESTAMPTZ

Coordinate TVMaze requests across pods sharing outbound IP. Short provider-specific backoff/Retry-After; independent of the Gemini 24-hour policy. Exact values are technical defaults to validate.

Refresh & new episodes

Serve cached data immediately; enqueue a coalesced refresh when older than configurable 24h. A scheduled worker also refreshes linked shows so status changes do not require opening the webapp. Short provider backoff, expiring leases and idempotent catalog writes apply across pods.

Evaluate known future episode air timestamps when they pass, independently of the 24h fetch cadence. Newly aired, unwatched regular episodes after the show-seen watermark change Seen → To be seen, set New episodes available and increment affected versions. Preserve position/checkmarks/history. Newly published provider data is detected on refresh; no instant discovery guarantee.

Do not downgrade because of failed refresh, incomplete catalogs or an old unchecked episode. Use successful metadata plus the stored seen watermark. A show without aired regular episodes cannot be marked Seen by an empty-set check.

Technical proposals for review: unknown air date/time permits explicit manual watched marking; known future episodes remain blocked; automatic matching requires a single exact title match with corroborating identifiers/year when available; replacing an already linked show requires an explicit Change show action and confirmation before resetting old show-specific progress. These are not new approved product decisions.

tvmaze_search_cache · Persistent autocomplete responses

query_key TEXT PK; normalized_query TEXT; result_payload JSONB; fetched_at TIMESTAMPTZ; expires_at TIMESTAMPTZ; refresh_lease_token UUID NULL; refresh_lease_until TIMESTAMPTZ NULL

The key includes provider, query normalization and any result-affecting parameters. Normalize case and redundant query whitespace for cache lookup only; preserve stored entity titles and their exact duplicate identity. Cache the complete returned candidate list and paginate its presentation locally—do not discard results beyond the first eight.

Suggested cache defaults for technical review: positive results 24h, empty results 15m, bounded stale-on-provider-error window 7d; all configurable in application.yml. Fresh cache hits make no TVMaze request. Atomically claim a short refresh lease to coalesce identical concurrent searches; release database transactions before network calls. Reuse stale results within the configured window while refreshing, clearly indicating stale/provider-unavailable state when appropriate.

Do not cache HTTP failures as empty results. Separate provider cooldown/backoff still applies. Expired refresh leases recover after a pod crash. Use bounded cleanup and a configurable cache-row limit; avoid logging raw search queries unnecessarily.

Required tests: repeated queries, restart persistence, two pods requesting the same key, case/whitespace-equivalent queries, expiry and empty-result TTL, provider failure without false no-results, late response suppression and all suggestions remaining accessible.

Identified title & editable alias

Once a TV show is identified, its canonical title is read-only. Show the user’s optional alias immediately after it in the entity header, table and board cards. The alias can be added, edited or cleared later; title search also matches it.

Keep alias TEXT NULL on the owner-scoped entity_tv_shows mapping. It is not part of provider identity, does not alter TVMaze search IDs, and never changes episode progress or completion history. An unmatched manually created title remains editable.

Enforce title locking on the backend, not just the UI: reject entity-title mutations for a matched TV show with IDENTIFIED_TITLE_READ_ONLY. Use versioned alias updates. Provider catalog name corrections are separate from user edits and retain stable identity.

Show identity & corrections

  • Change show: provide an explicit action to replace a wrong match. Show a confirmation explaining that the old season/episode position and episode checkmarks will be reset. Cancel leaves everything unchanged; confirm changes the mapping and resets only show-specific progress atomically. No silent remapping.
