Server confirms storage. Green success transitions immediately to blue saved; red means error. Initial and in-progress appearances are visual proposals below.

What is stored: URL + title + Readability's extracted article HTML, submitted as a string and stored in PostgreSQL TEXT. This preserves extracted structure, not the whole original page. Capture-state behavior
  • Save: one click captures and sends immediately, with no review step. Confirm success only after the server responds; request timeout is 60 seconds.
  • Duplicate: exact URL matching. Ask Update existing / Cancel. Automatically fill missing content, but never replace existing content without explicit user instruction.
  • Error: a missing confirmation does not prove that nothing was stored. The user retries from the article; no stored queue or special retry deduplication. Existing duplicate rules apply.

Preview only: all controls above switch prepared illustrations. No page is read or saved. Quiet utility is selected. Ready/saving colors remain proposals. Saved is blue; errors are red. Green success transitions immediately to blue, so no separate green resting screen is shown.

Entity lists

Manual entry, title editing, creation/completion dates, and Table / Board / By year views. Exactly one entity type stays selected.

Interactive entities →

Books: To read / Reading / Read. Movies & TV shows: To be seen / Seen. Games: To play / Playing / Finished.

Completion years use UTC history timestamps, not creation dates: one entity row with its yearly completion count. Completion uses supplied time or server-now automatically. Automatic category/entity extraction is later work.
