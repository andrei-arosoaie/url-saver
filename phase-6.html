Phase 6 · Automatic Entity & Category Identification

Identify what was captured.

Automatically identify a captured page’s category and the books, movies, TV shows or games it mentions.

Delivery order: Phase 1 — Functionality → Phase 2 — Timeline & Entities → Phase 3 — Extension Retries → Phase 4 — Screenshots & storage → Phase 5 — Category Management → Phase 6 — Automatic Identification → Phase 7 — Article Connections → Phase 8 — Authentication & Authorization.

Scope

  • Choose from all enabled account categories, including AI and custom categories.
  • Identify the central subjects, excluding passing mentions; allow multiple subjects and mark exactly one as the main subject.
  • Analyze article text only. Run automatically after the first save, then only on explicit request. Populate the metadata used by the timeline and entity Add action.
  • Preserve manual corrections and existing entity links until explicit user replacement.
  • Entity list membership remains an explicit Add action; identification alone does not enroll entities or rewrite completion history.

Automatic identification is Phase 6. Phase 2 continues to support manual category/name editing and manual entity entry.

Architecture

  • Spring AI 2.0.2: latest stable reference release checked 31 October 2026; compatible with Spring Boot 4.1.x. Keep framework and provider types inside infrastructure adapters, behind application interfaces and Java records.
  • Providers: OpenRouter first, using openrouter/free; Groq fallback, using free-tier openai/gpt-oss-120b. Provider order, models and credentials are configured through mounted YAML. Additional adapters must not change application contracts.
  • Manual input wins: track user-supplied versus AI-generated category and name separately. AI fills missing fields only. Never overwrite manual edits unless explicitly requested. Recheck field ownership before applying a background result.
  • Durable background processing: persist pending identification jobs in PostgreSQL so work survives restarts. Saving does not wait for AI. Analyze article text only, automatically after the first save; subsequent attempts require user request.
  • Fallback and cooldown: try the other eligible provider when the first fails. Show failure if neither succeeds. Confirmed quota exhaustion or a configured consecutive-failure threshold disables that provider temporarily. Initial cooldown: 1 day, configurable. Initial consecutive-failure threshold: 3, configurable through application YAML properties. Do not keep calling a provider during cooldown.
  • Skip rules: skip identification when article text is unavailable or all identification fields have been supplied manually.
  • Long articles: process large text in chunks, stopping as soon as there is enough information to identify the subjects and fill missing fields. Do not process remaining chunks unnecessarily; minimize model calls and token usage.
  • Subjects: allow multiple central subjects, with exactly one marked as main when subjects are identified. Exclude passing mentions.
  • Existing behavior: preserve entity links and completion history. Identification does not enroll entities in a list; Add remains explicit.

Z.ai · GLM-4.7-Flash — free model; account limits require checking
Access & payment
Create an account and a Standard API key. The pricing page lists this exact model as free. The quick-start says to top up only if needed; it does not establish a universal card, phone-verification or minimum-balance requirement for every account.
Quota & exhaustion
Exact limits are shown in the signed-in rate-limit dashboard. No universal daily token allowance or reset schedule was verified, so an articles/day guarantee cannot be given. Handle quota/concurrency errors; do not switch to a paid model automatically.
Data & location
API terms say end-user content is not used to improve services without explicit agreement. The API data-processing appendix says request content is not stored; however, the FAQ also describes cloud prompt caching with an unpublished retention period. Do not treat this as an unconditional zero-retention guarantee without clarification. Processing is generally in Singapore.
Using it in Know
The API terms cover integration into applications and impose content, intellectual-property and permitted-use restrictions. GLM Coding Plan quotas are separate and cannot be used to power this application. No fixed lifetime of the free offer is promised here.

OpenRouter · free models — 50 requests/day without buying credits
Access & payment
An account and API key are needed. Models ending in :free do not require buying credits. Other models advertised at $0 can require a funded account. Purchasing $10 of credits raises the free-variant cap to 1,000 requests/day; it is an upfront purchase, not a monthly free-tier subscription. Failed requests count toward the daily cap.
Quota & exhaustion
20 requests/minute and 50/day before the qualifying purchase. Extra keys/accounts do not increase capacity. Providers can impose additional limits; the reset timezone was not established in the cited documentation. Rate exhaustion returns 429. A negative paid credit balance can also block free calls. Availability and model selection can change; openrouter/free can choose different models between requests.
Charges & credits
Free-model inference is $0; paid models, plugins and tools can spend credits. Keep paid fallbacks and auto-recharge off for a zero-spend setup. Purchased credits may expire after 365 days; optional auto-recharge charges the configured payment method when the chosen threshold is reached.
Data & use
OpenRouter does not train on API inputs/outputs. Prompt logging and product-improvement sharing are optional and off by default, with safety-screening exceptions; request metadata is retained. Upstream providers have their own training and retention rules. Free and paid model training preferences are separate settings. Opting out of training restricts routing; it is not the same as zero retention. Provider licenses and model terms still apply. Free plans have no contractual SLA or EU-only routing commitment.

Cloudflare · Qwen3 30B — daily compute allowance, not a fixed number of calls
Access & payment
A Cloudflare account, Account ID and Workers AI API token are needed. The listed Qwen model can use the Workers Free allocation; buying a domain, moving the backend to Cloudflare, or subscribing to Workers Paid is unnecessary for this REST integration.
Quota & reset
10,000 neurons/day, shared across Workers AI usage, resetting at 00:00 UTC. Qwen3 30B uses 4,625 neurons/million input tokens and 30,475/million output tokens. The example consumes about 29.22 neurons/article: approximately 342/day before other usage. Default text-generation rate is 300 requests/minute; model-specific limits can differ.
Exhaustion & charges
On Workers Free, requests fail after the allowance; paid overage requires an upgrade. Workers Paid bills compute above the free allocation, with a separate plan fee. Some frontier models require paid billing or prepaid credits even though other models are free. Those conditions do not make every model in the catalog free.
Data & use
Workers AI does not train on customer content. Standard stateless inference retains content only as needed to process and deliver it, subject to security/legal exceptions. Enabling AI Gateway logging/caching, storage, batch or other stateful features changes retention. Third-party model licenses apply; this free allocation does not establish EU-only processing.

Groq · GPT-OSS 20B and 120B — token limits usually bind before request limits
Access & payment
Create a GroqCloud account and API key. The Free tier is distinct from the Developer tier. Paid access requires an explicit upgrade and a valid payment method; it is not simply a free quota followed by automatic overage. Check any account-verification requirements during signup.
Limits for each listed model
30 requests/minute, 1,000 requests/day, 8,000 tokens/minute and 200,000 tokens/day. The organization shares its limits across keys and users; account-specific limits can differ. At 5,200 tokens/article, the daily token limit allows about 38 articles/day, despite the 1,000-request cap. Exact remaining allowances/reset timing come from the console and response headers; no UTC reset time is assumed here.
Exhaustion & charges
Exceeding a rate limit returns 429; respect Retry-After. Developer access bills usage, with invoices at month-end or progressive thresholds starting at $1. Upgrading is a change to paid billing, not a guarantee that the previous free token allowance remains included.
Data & use
Usage metadata is retained. Inference content is not normally retained, but reliability/abuse logs can contain it for up to 30 days or longer if legally required. All customers may enable Zero Data Retention in Data Controls; features requiring stored state then become unavailable. Groq's Trust Center says customer data is not used to train models for Groq's own purposes. Model licenses and Groq service/use policies apply.

Google · Gemini 2.5 / 3.1 / 3.5 Flash-Lite — regional eligibility matters
Models covered
The pricing page lists free standard text input/output for Gemini 2.5 Flash-Lite, Gemini 3.1 Flash-Lite and Gemini 3.5 Flash-Lite. Their paid annual estimates in the table are separate from free eligibility. Each model has its own active limits; a free listing does not guarantee available capacity.
Access & region
Use a Google account, project and API key. New accounts start on the Free tier; billing is enabled separately. API terms require users aged 18+, supported regions, and developer/professional use. Applications offered to EEA, UK or Swiss users must use Paid Services. Direct AI Studio/free-quota availability in those regions does not remove that application restriction.
Quotas & exhaustion
Check AI Studio's active limits separately for each of the three models: requests/minute, input tokens/minute, requests/day and any model-specific token/day caps. Limits apply per project, not per key. Daily request quotas reset at midnight Pacific time. A universal fixed article/day figure is not published for these account-dependent limits. Exhaustion produces a rate-limit error; free calls do not automatically become paid without billing setup.
Data & charges
Outside the EEA/UK/Switzerland, unpaid-service content may improve Google products and be human-reviewed; sensitive content should not be submitted under those terms. The regional exception applies paid-service data treatment even to unpaid quota in EEA/UK/Switzerland. Paid-service prompts/responses are not used for product improvement. Linking an active billing account changes Gemini API access to Paid Services and paid API usage is chargeable. Cloud trial credits are not a substitute for Gemini API credit.

Implementation guide

  1. Backend review: durable PostgreSQL jobs, OpenRouter/Groq adapters, manual-field provenance, fallback and cooldown. Complete HTTP/database integration tests cover normal flows and concurrent edits, deletion and worker recovery.
  2. Webapp review: identification status, field provenance, multiple subjects/main subject and explicit retries are implemented. Only chosen metadata fields become manual; unchanged fields remain available to AI.
  3. Release review: verify configured providers and clients before deployment.
