Architecture & security

3 - Architecture and security

Shared React presentation

Capacitor packages the existing React components and CSS. The same responsive navigation, screen hierarchy, controls and visual tokens as the web app, with restored selection and accessible editors.

Shared contracts

Repositories use existing REST APIs. Server versions govern edits. Conflicts require review; unconfirmed writes are never replayed automatically. UTC completion precision is preserved.

Dedicated Android identity

Add a native OAuth client, browser-based PKCE sign-in and verified App Links. Keep refresh credentials encrypted with Keystore-held keys. No embedded sign-in or provider secrets.

The current backend allowlists web and Firefox clients. Native authorization requires backend work. The trusted React app runs in the Capacitor WebView; saved article HTML stays in the existing script-disabled sandbox with no native bridge access.

Implementation guide

Active project: android/capacitor. Preserved prototype: android/kotlin. The initial build uses fictional preview data; production sign-in, API integration and Share to Know are remaining checkpoints.

  4. Deliver Timeline, reader, screenshots, metadata, identification and connections.
  5. Deliver entities, precise history, TV progress, categories and profile controls.
  6. Verify accessibility, hostile HTML, process recreation and phone/tablet resizing; prepare a reproducible release artifact.

Release gates include contract/security tests, Android WebView/device instrumentation, lint, unit tests and assembly, plus physical phone and tablet checks. Signing and distribution need configured ownership and credentials.
